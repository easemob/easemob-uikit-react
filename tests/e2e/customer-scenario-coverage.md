# 客户通话场景规范覆盖清单

对照文件：测试提供的 `customer-scenario-spec.md`（《通话测试规范》）。本清单按规范编号统计，不按 Playwright `test()` 数量统计。现有测试依据为本目录的 `call-signaling.spec.ts` 和 `callkit.spec.ts`；`call-signaling-coverage.md` 对照的是另一份旧的信令设计清单，编号不能混用。

用户已确认原有 29 条信令 E2E 能通过。下表保留本轮补用例前的覆盖基线，便于核对缺口来源；本轮编写进度见文末。状态表示**覆盖程度**，不是最新运行结果。

| 状态       | 判定口径                                                                   |   数量 |
| ---------- | -------------------------------------------------------------------------- | -----: |
| 主结论已有 | 已有测试执行该编号的主要客户动作并验证主要结果；通用断言仍可能需要统一补强 |     11 |
| 部分覆盖   | 已有相关流程，但缺少规范指定的分支、观察端、界面、快照或媒体验证           |     31 |
| 缺失       | 没有能验证该编号主结论的对应场景；相近流程不折算覆盖                       |     41 |
| **合计**   | **83 个规范编号**                                                          | **83** |

测试归属建议：服务端操作、快照、事件、多端、离线和时序优先放在 `call-signaling.spec.ts`；规范要求实际界面或媒体效果时，放在 `callkit.spec.ts`，并与信令断言关联。真实 Wi-Fi／蜂窝切换、系统推送与真机专项需要设备测试环境，不能以浏览器模拟结果充当通过。

上述“主结论已有”仅表示动作和主要结果已有对应测试，不免除规范第 1、2 节的共用要求。实施时建议先将以下检查做成可复用断言，再用于新增和部分覆盖用例：

1. 就绪且在线的相关端分别取得服务端快照，核对同一 `callId`、类型、媒体、终态、结束原因、参与者状态和有效设备；离线或查询失败的端待恢复后再核对。
2. 比较 `createdAt`、`establishedAt`、`endedAt`、成员 `acceptedAt`／`leftAt` 的存在性和不变性；无接听者不得有接听时间。
3. 对照发起端操作响应与其他端通知／快照，检查同一次操作没有重复状态变化；呼叫不进入普通消息或增加未读。
4. 每条用例独立清理，并在要求终止的场景验证账号不再占线、可立即再拨。
5. 规范要求界面和媒体的场景必须在 CallKit／真机层观察；只调用信令 API 不能宣称声音、画面、铃声或资源清理通过。

公开 SDK 快照目前不含 `revision`（见 `call-signaling-coverage.md` 和 `F-02/F-11` 断言）。对于规范里的“版本不变／不小于已见版本”，需先确认 SDK 可观察的替代结果，不能凭空给公开快照添加字段。
